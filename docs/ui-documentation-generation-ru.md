# Как формируется документация из UI мода

> Документ первоначально описывал старый генератор. Раздел ниже фиксирует модернизацию, выполненную после анализа; последующие разделы сохраняют подробную трассировку исходной архитектуры и объясняют причины изменений.

## Результат модернизации

Автоматическая генерация гайда в стиле `darknessawaiter.github.io/blt-guide` технически реализуема без отдельного frontend-фреймворка: существующая модель уже предоставляет команды, награды, классы, достижения и другие глобальные настройки. Генератор оставлен статическим (`index.html`, `style.css`, `guide.js`), но получил современную адаптивную тему, компактное оглавление и клиентский поиск.

Исправлены ключевые проблемы старого процесса:

- из `HeroClassDef.GenerateDocumentation()` удален цикл, вызывавший `EquipHero.UpgradeEquipment(Hero.MainHero, ...)` для шести тиров; именно он изменял экипировку персонажа игрока ради скриншотов;
- API и реализация генерации изображений удалены, а старые `blt_img_*.png` очищаются при следующей генерации;
- синонимы команд выводятся из `Command.AliasList` отдельной колонкой и автоматически участвуют в текстовом поиске;
- основная команда и каждый синоним становятся отдельной кнопкой: нажатие копирует значение в буфер обмена и показывает подтверждение;
- подробные настройки команд и наград свернуты под `Details`, чтобы основной справочник оставался коротким;
- добавлены фильтры разделов `All`, `Commands`, `Rewards`, `Classes` и `More`, работающие совместно с поиском;
- классы выводятся компактными раскрывающимися карточками;
- в шапке размещена ссылка на авторское описание команд: `https://lait96.github.io/Bannerlord-Twitch-lait/`;
- ошибки записи файлов больше не подавляются внутри `SaveAsync`, поэтому UI не сообщает об успехе при неудачной записи;
- предупреждение о необходимости перезагрузить сохранение удалено вместе с изменяющей состояние логикой.

## Краткая схема

После нажатия **Generate Documentation** мод берет текущие настройки редактируемого профиля, преобразует включенные команды, награды и поддерживающие документацию глобальные конфигурации в набор HTML-фрагментов, добавляет оглавление, заголовок и введение, а затем записывает статический сайт из `index.html`, `style.css` и, если их генерация поддерживается текущей сборкой, изображений.

Основная цепочка вызовов:

```text
BLTConfigureWindow.xaml
  -> GenerateDocumentationButton_OnClick()
  -> DocumentationGenerator.Document(EditedSettings)
  -> Settings.GenerateDocumentation(generator)
     -> команды
     -> награды Twitch
     -> глобальные конфигурации
  -> DocumentationGenerator.SaveAsync(title, introduction)
  -> %USERPROFILE%\Documents\Mount and Blade II Bannerlord\Configs\BLT-documentation
```

## 1. Точка входа в UI

Вкладка `Documentation` и кнопка `Generate Documentation` описаны в `BannerlordTwitch/BLTConfigure/BLTConfigureWindow.xaml`. Событие `Click` связано с методом `GenerateDocumentationButton_OnClick` из `BLTConfigureWindow.xaml.cs`.

Перед генерацией обработчик проверяет `Campaign.Current?.GameStarted`. Если кампания не запущена или сохранение не загружено, выполнение останавливается с сообщением об ошибке. Это ограничение нужно не только для UI: некоторые документируемые конфигурации используют текущее состояние кампании и игровые API.

При успешной проверке обработчик:

1. отключает кнопку, чтобы пользователь не запустил второй процесс одновременно;
2. показывает статус `Generating Documentation...`;
3. создает новый `DocumentationGenerator`;
4. вызывает `Document(ConfigurationRoot.EditedSettings)`;
5. вызывает `SaveAsync(ConfigurationRoot.DocsTitle, ConfigurationRoot.DocsIntroduction)`;
6. показывает сообщение о завершении и снова включает кнопку.

`EditedSettings` — объект `Settings`, загруженный для активного профиля и редактируемый окном конфигурации. Поэтому документ строится по состоянию формы/профиля, а не путем повторного чтения YAML непосредственно в момент нажатия. Заголовок и вступление берутся отдельно из `AuthSettings.DocsTitle` и `AuthSettings.DocsIntroduction`; их поля на вкладке сохраняются через `ConfigurationRootViewModel`.

После попытки генерации игра показывает диалог с требованием перезагрузить сохранение, поскольку процесс может изменить игровое состояние. Диалог показывается и после исключения внутри основного `try/catch`; исключение составляет ранний выход, когда кампания не запущена.

## 2. Переход на главный поток игры

`DocumentationGenerator.Document()` сначала ожидает завершения ранее запущенной записи изображений, затем через `MainThreadSync.RunWaitAsync` вызывает:

```csharp
documentable.GenerateDocumentation(this)
```

В данном случае `documentable` — `Settings`, а `this` — генератор HTML. Перенос на главный поток позволяет обработчикам документации безопасно обращаться к объектам Bannerlord, состоянию кампании и игровому рендерингу.

Генератор не строит DOM. Он последовательно добавляет строки с HTML в список `content`, а заголовки для оглавления — в отдельный список `toc`. Интерфейс `IDocumentationGenerator` предоставляет методы для `div`, `details`, `summary`, заголовков, таблиц, строк и ячеек, абзацев, изображений, якорей и элементов карты.

## 3. Какие настройки попадают в документ

Корневую структуру определяет `Settings.GenerateDocumentation()`.

### Команды

Создается раздел `Commands` с таблицей из трех колонок: команда, описание и настройки. В таблицу включаются только элементы `Commands`, у которых `Enabled == true`.

- Название берется из `Command.Name`.
- Описание берется из `Command.Documentation`; если оно пустое, используется `Command.Help`.
- Для `HandlerConfig`, реализующего `IDocumentable`, вызывается его собственный `GenerateDocumentation()`.
- Для остальных непустых `HandlerConfig` используется автоматическое документирование через `DocumentationHelpers.AutoDocument()`.

### Награды за баллы канала

Раздел `Channel Point Rewards` строится аналогично и включает только награды с `Enabled == true`.

- Название берется из `RewardSpec.Title`.
- Описание берется из `Reward.Documentation`; если оно пустое, используется `RewardSpec.Prompt`.
- Настройки обработчика выводятся вручную через `IDocumentable` либо автоматически через `AutoDocument()`.

### Глобальные конфигурации

Генератор перебирает `GlobalConfigs`, извлекает `GlobalConfig.Config` и оставляет только объекты, реализующие `IDocumentable`. Каждый такой объект сам добавляет свои разделы в общий генератор. Глобальная конфигурация без `IDocumentable` в итоговый документ не попадет.

Таким образом, состав документа определяется одновременно текущим профилем, флагами `Enabled`, фактическими типами `HandlerConfig` и реализацией `IDocumentable` в подключенных модулях.

## 4. Ручное и автоматическое формирование содержимого

### Ручной режим: `IDocumentable`

Тип может полностью управлять своим представлением, реализовав:

```csharp
void GenerateDocumentation(IDocumentationGenerator generator)
```

Так формируются специализированные таблицы, описания, награды, достижения, способности, классы героев и другие предметные разделы. Вложенные объекты также могут делегировать генерацию другим реализациям `IDocumentable`.

Например, `GlobalCommonConfig.GenerateDocumentation()` сначала автоматически выводит помеченные свойства, затем отдельно формирует включенные серии убийств и достижения, вызывает генерацию документации вложенных требований и способностей, добавляет документацию системы улучшений и при включенной карте использует текущие данные кампании.

### Автоматический режим: `DocumentationHelpers.AutoDocument`

Автоматический режим рекурсивно обрабатывает значение:

- `bool` превращается в локализованное `Enabled` или `Disabled`;
- примитив, перечисление или строка выводятся через `ToString()`;
- коллекция превращается в таблицу, где каждый элемент обрабатывается рекурсивно;
- сложный объект передается reflection-обходу свойств.

У сложного объекта выводятся **только свойства с атрибутом `[Document]`**. Они группируются по `[Category]`, категории сортируются по `[CategoryOrder]`, а свойства внутри категории — по `[PropertyOrder]`. Название колонки берется из `[DisplayName]` с локализацией или формируется из имени свойства; описание берется из локализованного `[Description]`. Значение свойства снова проходит через `AutoDocument`, поэтому поддерживается вложенная структура.

Атрибуты UI без `[Document]` сами по себе не включают свойство в документацию.

## 5. HTML, оглавление и локализация

Методы `H1`, `H2` и `H3` одновременно:

1. добавляют заголовок в основной контент;
2. создают числовой якорь;
3. добавляют ссылку на него в `toc`.

При `SaveAsync(..., addTOC: true)` оглавление вставляется в начало накопленного содержимого. Перед ним добавляются `DOCTYPE`, UTF-8 meta-тег, подключение `style.css`, заголовок документа и введение. В конце закрывается контейнер страницы.

Локализуемые строки вызывают расширение `Translate()`, поэтому язык результата зависит от активной локализации игры во время генерации. Пользовательские названия и описания берутся из текущих настроек.

Генератор добавляет переданные строки как готовый HTML и не выполняет общего HTML-экранирования. Следовательно, специальные символы или HTML в пользовательских полях могут влиять на разметку результата.

Таблицы по умолчанию помещаются в `<details>` и получают `<summary>`, то есть в браузере они отображаются сворачиваемыми. Конкретное оформление задается CSS-файлом мода.

## 6. Изображения

При вызове `Img(...)` генератор сразу добавляет в HTML ссылку вида `blt_img_N.png` и регистрирует ожидаемую запись изображения в `pendingImages`. Перед документированием и сохранением `WaitForPendingImagesAsync()` ждет до 100 раз по 100 мс, то есть примерно до 10 секунд, после чего очищает список ожидания.

Для полученной игровой текстуры предусмотрены сохранение во временный файл, исправление порядка красного и синего каналов и перенос PNG в каталог документации. Однако вызовы игрового рендера предметов включены только для определенных условных символов компиляции (`e159` или `e1510`), а рендер персонажа в текущем коде закомментирован. Поэтому возможность реально получить изображения зависит от варианта сборки; HTML-ссылка может быть добавлена и без созданного PNG.

## 7. Запись результата

Файлы создаются в каталоге:

```text
%USERPROFILE%\Documents\Mount and Blade II Bannerlord\Configs\BLT-documentation
```

`DocumentationGenerator.SaveAsync()`:

1. создает каталог, если его нет;
2. записывает накопленные строки в `index.html` через `File.WriteAllLines`;
3. удаляет прежний `style.css`, если он существует;
4. копирует `Bannerlord-Twitch-Documentation.css` из установленного модуля под именем `style.css`.

Кнопка `Open Documentation` открывает `index.html`, а `Open Documentation Folder` — каталог результата. Обе команды предварительно проверяют существование цели.

## 8. Обработка ошибок и особенности реализации

- Исключения из `Document()` или внешней части `SaveAsync()` перехватываются обработчиком кнопки и показываются в статусе UI.
- Ошибки создания каталога, записи HTML или копирования CSS перехватываются **внутри** `SaveAsync()` и только отправляются в лог через `Log.Error`. Они не пробрасываются в обработчик кнопки, поэтому UI может показать `Documentation Generation Complete`, даже если файлы записаны не полностью.
- Генератор накапливает состояние (`content`, `toc`, счетчики якорей и изображений) в экземпляре. UI каждый раз создает новый экземпляр, поэтому повторное нажатие начинает новый документ.
- Существующий каталог целиком не очищается. `index.html` перезаписывается, `style.css` заменяется, но старые изображения, которые больше не используются, могут остаться.
- Формирование документа может вызывать предметную логику, читающую состояние кампании или создающую игровые представления. Именно поэтому UI требует загруженную кампанию и после операции рекомендует перезагрузить сохранение.

## 9. Основные файлы реализации

- `BannerlordTwitch/BLTConfigure/BLTConfigureWindow.xaml` — вкладка и кнопки документации.
- `BannerlordTwitch/BLTConfigure/BLTConfigureWindow.xaml.cs` — проверки, последовательность вызовов, статусы и открытие результата.
- `BannerlordTwitch/BLTConfigure/UI/ConfigurationRootViewModel.cs` — источник редактируемых настроек, заголовка и введения.
- `BannerlordTwitch/BannerlordTwitch/Settings/Settings.cs` — корневая структура разделов команд, наград и глобальных конфигураций.
- `BannerlordTwitch/BannerlordTwitch/Documentation/DocumentationGenerator.cs` — накопление HTML, оглавление, изображения и запись файлов.
- `BannerlordTwitch/BannerlordTwitch/Documentation/DocumentationHelpers.cs` — reflection-генерация по `[Document]`.
- `BannerlordTwitch/BannerlordTwitch/Documentation/IDocumentable.cs` и `IDocumentationGenerator.cs` — контракты расширения.
- `BannerlordTwitch/BannerlordTwitch/Documentation/DocumentAttribute.cs` — маркер автоматически документируемого свойства.
- `BannerlordTwitch/BannerlordTwitch/_Module/Bannerlord-Twitch-Documentation.css` — исходные стили итоговой страницы.

## 10. Актуальная реализация в стиле blt-guide

Разделы 1–9 выше описывают исходный механизм и причины его проблем. После переработки действуют дополнительные правила:

- при английском языке игры создаётся только английская страница;
- при любом другом языке один HTML содержит текущую локализацию и оригинальный английский, между ними можно переключаться;
- английский текст берётся из fallback-части локализуемых строк без изменения глобального языка игры;
- ссылки содержания сами включают нужный верхний фильтр, поэтому переходы остаются рабочими;
- классы показаны сеткой кнопок, а выбранный класс — в единственной панели на всю ширину;
- перед содержанием появился короткий стартовый маршрут по основным этапам игры;
- команды и синонимы можно копировать нажатием;
- вкладка настроек документации и оболочка русского гайда локализованы;
- авторское описание команд открывается по адресу `https://lait96.github.io/Bannerlord-Twitch-lait/`;
- изображения больше не создаются, а генерация не вызывает экипировку героя и не изменяет его предметы.

Последующее уточнение приблизило содержимое к эталону: стартовый маршрут теперь подставляет реальные включённые команды активного профиля, силы классов показываются таблицами по уровням, а общие требования уровней класса вынесены в отдельную таблицу. В настройках снова приведена пошаговая бесплатная публикация через Neocities.

Оглавление удалено. Итоговый порядок страницы: заголовок и введение, ссылка на документацию разработчика, стартовый гайд, отдельная панель поиска и фильтров, затем фильтруемое содержимое. Общий фильтр «Ещё» заменён доступными категориями настроек, серий убийств, достижений и карты; отсутствующие категории скрываются автоматически.

Система улучшений семантически относится к фильтру «Настройки». Для полной документации требуется загруженное сохранение: часть описаний команд читает зарегистрированные игрой навыки, культуры и другие объекты кампании. Генерация из главного меню намеренно заблокирована, чтобы не создавать неполный гайд. Русский UI вкладки выбирается напрямую по языку Bannerlord, поскольку локализация отдельного конфигуратора может загружаться позже создания окна.
